# 1.5.0 small fixes (chart side) — 2026/11/16

Branch `fix/1.5.0-small-20261116`. Approved mockup "1.5.0 Small Fixes", item 15 (#344). The
agent change is recorded in issassist-tsm-agent's `docs/projects/2026-11-16-1-5-0-small-fixes.md`.

## What

The agent's `[tasks] heartbeat_timeout` was hard-coded to `300.0` in
`templates/issassist/tsm-agent/configmap.yaml`. Following the Kubernetes-first rule it now
comes from `tsmAgent.tasks.heartbeatTimeout` (default `300`) in values.yaml. The agent reads it
from the mounted `config.toml`, as it reads every other `[tasks]` option; the ConfigMap is the
agent's config file, so there is no separate env var.

The agent's new reaper closes a process row whose worker is gone after
`2 × heartbeat_timeout`, so this value now also sets that grace period.

## Template choices

* `$tasks := .Values.tsmAgent.tasks | default dict` — an upgrade with `--reuse-values` keeps
  old values with no `tasks` key and must still render (same pattern as `tapeSync`).
* `hasKey` rather than `default`, so an explicit `0` is refused instead of silently becoming
  300. Values ≤ 0 `fail` the render.
* Rendered as `printf "%.1f"`, matching the TOML float the agent's sample config uses.

## Check

`scripts/check_tsm_agent_tasks_render.sh`: default, a chosen value, a fractional value, old
values without `tasks`, exactly one line, and 0 / -5 refused. Against the original template, 4
of the 7 checks fail. There is no CI workflow in this repo; the render checks are run by hand.
`helm lint` fails identically on review (missing `kubernetes-secret-generator` dependency
metadata) — pre-existing, not touched here.
